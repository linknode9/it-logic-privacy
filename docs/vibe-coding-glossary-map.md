# 実務語マップ（vibe coding / 非エンジニアのための実務IT用語）

IT Logic のコンテンツ拡充用 設計図。

## このマップの目的

ITパスポート・基本情報などの**資格シラバスには載らないが、実際に手を動かすと最初に詰まる用語**を分類したもの。
資格は「数年変わらない普遍知識」を出題する設計のため、Git・API・デプロイ・環境変数といった
"現場語" や、React・Vercel などの製品名を扱わない。ここが IT Logic の独自カテゴリ＝差別化になる。

### 使い方
- 現在の収録語（約1,300語・ITパスポート網羅済み）と突き合わせ、未収録の語を洗い出す「不足語チェックリスト」として使う。
- 解説文はすべて自前で書く（他社解説のコピーは著作権NG）。本ファイルの一言解説は下書きの叩き台。
- 「構造で理解」のコンセプトに沿い、各語は関連語とのつながりで提示すると価値が高い。

凡例：⭐=最優先（詰まりやすさ・頻出度が高い）

## 1. バージョン管理・コード共有（Git / GitHub）

| 用語 | 一言解説（叩き台） |
|---|---|
| Git ⭐ | コードの変更履歴を記録・管理する仕組み。「セーブの履歴を全部残せる装置」 |
| GitHub ⭐ | Gitのコードをネット上に置いて共有・共同作業する場所 |
| リポジトリ（repo）⭐ | プロジェクト一式を入れる「箱」。コードと履歴がまとまっている |
| コミット ⭐ | 変更に名前を付けて履歴に1区切り保存すること |
| プッシュ ⭐ | 手元の変更をGitHub（ネット側）に送ること |
| プル / フェッチ | ネット側の最新を手元に取り込むこと |
| クローン | リポジトリを丸ごと自分のPCにコピーすること |
| ブランチ ⭐ | 本流から枝分かれした作業線。壊さず試せる |
| マージ | 枝分かれした変更を本流に合流させること |
| コンフリクト（衝突） | 同じ箇所を別々に変更してぶつかった状態 |
| プルリクエスト（PR）⭐ | 「この変更を取り込んで」と依頼するGitHubの仕組み |
| main / master | 本流のブランチ名（標準の幹） |
| .gitignore | Gitで管理しないファイルを指定する設定 |
| README | プロジェクトの説明書ファイル |
| フォーク | 他人のリポジトリを自分用に複製すること |

## 2. 動かす・公開する（ローカル〜本番）

| 用語 | 一言解説（叩き台） |
|---|---|
| ローカル（localhost）⭐ | 自分のPCの中だけで動いている状態。`localhost` は「自分自身」 |
| ポート ⭐ | 1台のPC内でサービスを区別する番号（例: 3000番） |
| サーバー | リクエストを受けて処理を返す側のコンピュータ／プログラム |
| ビルド ⭐ | 書いたコードを実際に動く形に変換・組み立てること |
| バンドル | 複数ファイルを1つにまとめること |
| デプロイ ⭐ | 作ったものを本番環境に公開・配置すること |
| ホスティング ⭐ | アプリやサイトをネット上に置いて公開してくれるサービス |
| 本番環境 / 開発環境 ⭐ | 公開用と、手元の試作用の区別 |
| ステージング環境 | 本番直前の確認用環境 |
| ドメイン | サイトの住所（例: example.com） |
| DNS | ドメインをサーバーの場所に変換する仕組み |
| SSL / HTTPS | 通信を暗号化して安全にする仕組み（鍵マーク） |
| CDN | コンテンツを世界中に分散配信して速くする仕組み |
| CI/CD | 変更を自動でテスト・公開まで流す仕組み |

## 3. つなぐ（API・通信・データ形式）

| 用語 | 一言解説（叩き台） |
|---|---|
| API ⭐ | サービス同士をつなぐ窓口。「機能を外から呼び出す入口」 |
| APIキー ⭐ | APIを使うための合言葉。漏らすと悪用される |
| エンドポイント | APIの具体的な呼び出し先URL |
| リクエスト / レスポンス | 「お願い」と「返事」 |
| REST API ⭐ | APIの一般的な作法・形式の代表格 |
| JSON ⭐ | データをやり取りする標準の文字フォーマット |
| GET / POST | 取得する／送る、などの基本動作 |
| Webhook | 何か起きたら自動で通知を飛ばす仕組み |
| SDK ⭐ | あるサービスを使うための部品・道具一式 |
| ステータスコード（200, 404, 500）⭐ | 通信の結果を表す番号（成功/見つからない/エラー） |
| CORS | 別ドメインからのアクセス可否のルール。詰まりがち |
| レートリミット | 一定時間に呼べる回数の上限 |

## 4. 設定・秘密情報・認証

| 用語 | 一言解説（叩き台） |
|---|---|
| 環境変数 ⭐ | コードの外に置く設定値。鍵などをコードに直書きしないため |
| .env ファイル ⭐ | 環境変数（秘密情報）をまとめて書くファイル |
| シークレット / クレデンシャル | パスワードやキーなどの秘密情報 |
| トークン ⭐ | 本人確認・許可の証として使う文字列 |
| 認証（Authentication） | 「誰か」を確かめること（ログイン） |
| 認可（Authorization） | 「何をしてよいか」を決めること（権限） |
| OAuth ⭐ | 「Googleでログイン」などを実現する仕組み |
| セッション / Cookie | ログイン状態などを保持する仕組み |
| ハッシュ化 | パスワードを元に戻せない形にして保存すること |

## 5. 部品・依存関係（パッケージ管理）

| 用語 | 一言解説（叩き台） |
|---|---|
| ライブラリ ⭐ | よく使う機能をまとめた部品集 |
| フレームワーク ⭐ | アプリの骨組み・土台になる仕組み |
| パッケージ | 配布される部品の単位 |
| 依存関係（dependencies）⭐ | このアプリが動くのに必要な他の部品 |
| npm / yarn / pnpm ⭐ | 部品をインストール・管理する道具（JavaScript系） |
| package.json | 使う部品やコマンドを書いた設定ファイル |
| node_modules | インストールされた部品が入る巨大フォルダ |
| バージョン / セマンティックバージョニング | 部品の版番号（例: 1.2.3）とその意味 |
| インストール / アップデート | 部品を入れる／新しくする |

## 6. Web開発の基礎概念

| 用語 | 一言解説（叩き台） |
|---|---|
| フロントエンド ⭐ | 利用者が見て触れる画面側 |
| バックエンド ⭐ | 裏側でデータ処理や保存を行う側 |
| データベース（DB）⭐ | データを保存・検索する仕組み |
| HTML / CSS / JavaScript ⭐ | 画面の構造／見た目／動きの基本3点 |
| TypeScript | JavaScriptに型（安全装置）を足したもの |
| レンダリング | データを画面の形に描き出すこと |
| レスポンシブ | スマホ・PCで見た目を自動調整すること |
| コンポーネント | 画面を作る再利用可能な部品 |
| 状態（state） | 画面が今持っているデータの状態 |
| キャッシュ | 一度取ったものを取っておいて速くする仕組み |

## 7. データベース・データまわり

| 用語 | 一言解説（叩き台） |
|---|---|
| テーブル / レコード / カラム | 表・行・列。データの基本の入れ物 |
| SQL ⭐ | データベースを操作する言語 |

| スキーマ | データの構造・設計図 |
| バックアップ / リストア | 控えを取る／元に戻す |

## 8. AI開発・LLM まわり（vibe coding の中核）

| 用語 | 一言解説（叩き台） |
|---|---|
| LLM（大規模言語モデル）⭐ | 文章を理解・生成するAIの本体 |
| プロンプト ⭐ | AIへの指示文 |
| トークン ⭐ | AIが文章を扱う最小単位。料金や上限の計算基準 |
| コンテキスト（文脈窓）⭐ | AIが一度に考慮できる情報量の範囲 |
| ハルシネーション | AIがもっともらしい嘘を生成すること |
| ファインチューニング | モデルを特定用途に追加学習させること |
| RAG ⭐ | 外部資料を参照させて回答精度を上げる手法 |
| エンベディング（ベクトル） | 文章を数値化して意味で検索できるようにする技術 |
| エージェント ⭐ | 自分で道具を使い、手順を踏んで動くAI |
| MCP | AIに外部ツール／データをつなぐ標準規格 |
| 温度（temperature） | 回答のランダムさ・自由度の設定 |
| 推論（inference） | 学習済みモデルを実際に動かして答えを出すこと |

## 10. クラウド・インフラの基礎

| 用語 | 一言解説（叩き台） |
|---|---|
| クラウド ⭐ | 自分で持たず、ネット越しに借りるコンピュータ資源 |

| ストレージ | データの保存場所 |

## 11. トラブル・デバッグでよく出る語

| 用語 | 一言解説（叩き台） |
|---|---|
| バグ / デバッグ ⭐ | 不具合／それを直すこと |
| エラー / 例外 ⭐ | 異常が起きてプログラムが知らせる状態 |
| スタックトレース | エラーがどこで起きたかの足跡 |
| クラッシュ / フリーズ | 落ちる／固まる |
| タイムアウト | 待ち時間切れ |
| 再現性 | 同じ手順で同じ不具合が起きるか |
| ロールバック | 前の状態に戻すこと |
| 競合（race condition 等） | 同時処理がぶつかって起きる不具合 |

## 12. 現代スタックの固有名（製品・サービス名）

> 資格は固有名を扱わないが、vibe coding では避けて通れない。
> 更新が速いので「陳腐化前提」で、概念とセットで載せる。

| 用語 | 一言解説（叩き台） |
|---|---|
| React / Vue / Svelte | 画面を作るフロントエンドの代表的フレームワーク |
| Next.js | Reactを土台にした人気のWebフレームワーク |
| Node.js | サーバー側でJavaScriptを動かす土台 |
| Tailwind CSS | クラス指定で素早く見た目を作るCSS手法 |
| Vercel / Netlify | デプロイ・ホスティングの定番サービス |
| Supabase / Firebase | DB・認証などをまとめて借りられるサービス |
| AWS / GCP / Azure | 三大クラウド |
| Docker | コンテナ技術の代表 |
| VS Code | 定番のコードエディタ |
| Cursor / Claude Code / v0 / Bolt | AIでコードを書く開発ツール（vibe coding の入口） |
| Figma | デザインツール。開発と連携 |
