# 実務語マップ｜優先度つき完全版（12カテゴリ深掘り）

`vibe-coding-glossary-map.md` の各カテゴリを、語数一律ではなく **「重要度」で3段階に仕分け**して掘ったもの。

## 優先度の定義

| 記号 | レベル | 意味 |
|---|---|---|
| 🔴 | **必須**（知らないと話にならない） | これが分からないと、指示も質問もエラー相談も成立しない。最初の0→1で必ずぶつかる語 |
| 🟡 | **重要**（知っておくべき） | 詰まったとき自分で切り分け・検索・対処するために要る語 |
| 🟢 | **発展**（知っておいた方がいい） | 仕組みを一歩深く理解する／規模が大きくなると効いてくる語 |

> 収録の進め方：🔴 を全カテゴリ分そろえる → 🟡 → 🟢 の順。
> 🔴 だけで「最低限ひとり立ち」できる語彙セットになるよう設計している。

## 1. バージョン管理（Git / GitHub）

**🔴 必須**
- Git ― 変更履歴を全部残せる仕組み
- GitHub ― コードをネットに置いて共有・保存する場所
- リポジトリ（repo）― プロジェクト一式が入る箱
- コミット ― 変更に名前を付けて1区切り保存する
- プッシュ ― 手元の変更をGitHub側に送る
- プル ― GitHub側の最新を手元に取り込む
- クローン ― リポジトリを丸ごと自分のPCにコピー
- ブランチ ― 本流を壊さず試せる枝分かれ作業線
- main / master ― 本流（幹）のブランチ

**🟡 重要**
- マージ ― 枝分かれを本流に合流させる
- コンフリクト（衝突）― 同じ箇所の変更がぶつかった状態
- プルリクエスト（PR）― 「この変更を取り込んで」の依頼
- .gitignore ― Gitで管理しないファイルの指定
- README ― プロジェクトの説明書
- ステージング（git add）― コミットに含める変更を選ぶ

**🟢 発展**
- フォーク ― 他人のrepoを自分用に複製
- リバート / リセット ― 変更を取り消す／巻き戻す
- タグ / リリース ― バージョンに目印を付ける
- フェッチ ― 取り込まず最新情報だけ確認
- rebase ― 履歴を整理して付け替える

## 2. 動かす・公開する（ローカル〜本番）

**🔴 必須**
- ローカル / localhost ― 自分のPCの中だけで動く状態。`localhost`＝自分自身
- サーバー ― リクエストを受けて返す側
- ポート ― 1台の中でサービスを区別する番号（例: 3000）
- ビルド ― 書いたコードを動く形に組み立てる
- デプロイ ― 作ったものを本番に公開・配置する
- 本番環境 / 開発環境 ― 公開用と、手元の試作用
- ドメイン ― サイトの住所（example.com）

**🟡 重要**
- ホスティング ― アプリをネットに置いて公開してくれるサービス
- HTTPS / SSL ― 通信を暗号化して安全にする（鍵マーク）
- DNS ― ドメインをサーバーの場所に変換する仕組み
- 環境変数による設定切替 ― 開発と本番で値を変える（→4章）
- バンドル ― 複数ファイルを1つにまとめる
- ステージング環境 ― 本番直前の確認用

**🟢 発展**
- CDN ― 世界中に分散配信して速くする
- CI/CD ― 変更を自動でテスト〜公開まで流す
- ロードバランサ ― アクセスを複数サーバーに振り分ける
- リバースプロキシ ― 入口でリクエストを受けて裏に渡す
- ヘルスチェック ― 生きているか定期確認する

## 3. つなぐ（API・通信・データ形式）

**🔴 必須**
- API ― サービス同士をつなぐ窓口。機能を外から呼び出す入口
- APIキー ― APIを使う合言葉。漏らすと悪用される
- リクエスト / レスポンス ― お願い／返事
- JSON ― データをやり取りする標準の文字フォーマット
- エンドポイント ― 呼び出す先の具体的なURL
- ステータスコード（200/404/500）― 結果の番号（成功/無い/サーバーエラー）

**🟡 重要**
- GET / POST ― 取得する／送る、の基本動作
- REST API ― APIの最も一般的な作法
- SDK ― あるサービスを使うための部品・道具一式
- CORS ― 別ドメインからのアクセス可否のルール（よく詰まる）
- レートリミット ― 一定時間に呼べる回数の上限
- ヘッダー ― リクエストに付ける付帯情報（認証情報など）

**🟢 発展**
- Webhook ― 何か起きたら自動で通知を飛ばす
- GraphQL ― 必要なデータだけ取れるAPI方式
- WebSocket ― 双方向にリアルタイム通信する
- ペイロード ― 送受信する中身のデータ本体
- べき等性 ― 何回呼んでも結果が変わらない性質

## 4. 設定・秘密情報・認証

**🔴 必須**
- 環境変数 ― 鍵などをコードに直書きせず外に置く設定値
- .env ファイル ― 環境変数（秘密情報）をまとめるファイル
- APIキー / トークン ― 許可の証として使う秘密の文字列
- ログイン（認証）― 「誰か」を確かめる

**🟡 重要**
- 認証 / 認可 ― 「誰か」を確かめる／「何をしてよいか」を決める
- OAuth ― 「Googleでログイン」を実現する仕組み
- シークレット / クレデンシャル ― パスワードやキーなどの秘密情報
- セッション / Cookie ― ログイン状態を保持する仕組み
- .env を .gitignore に入れる ― 秘密をGitHubに上げない鉄則

**🟢 発展**
- ハッシュ化 ― パスワードを元に戻せない形で保存
- JWT ― 認証情報を持ち運ぶトークン形式
- 二要素認証（2FA/MFA）― ログインに2段階目を足す
- ロール / 権限（RBAC）― 役割ごとに操作範囲を分ける
- 暗号化 / 復号 ― 読めなくする／戻す

## 5. 部品・依存関係（パッケージ管理）

**🔴 必須**
- ライブラリ ― よく使う機能をまとめた部品集
- フレームワーク ― アプリの骨組み・土台
- インストール ― 部品を入れる
- 依存関係（dependencies）― このアプリが動くのに必要な他の部品
- npm ― 部品を入れて管理する道具（JavaScript系の定番）

**🟡 重要**
- package.json ― 使う部品やコマンドを書いた設定ファイル
- node_modules ― 入れた部品が溜まる巨大フォルダ
- バージョン（1.2.3）― 部品の版番号
- アップデート / アップグレード ― 部品を新しくする
- パッケージ ― 配布される部品の単位

**🟢 発展**
- セマンティックバージョニング ― 版番号の付け方ルール（メジャー/マイナー/パッチ）
- yarn / pnpm ― npmの代替・改良版
- ロックファイル ― 入れた版を固定して再現性を保つ
- pip / gem / cargo ― 他言語のパッケージ管理
- monorepo ― 複数プロジェクトを1リポジトリで管理

## 6. Web開発の基礎概念

**🔴 必須**
- フロントエンド ― 利用者が見て触れる画面側
- バックエンド ― 裏でデータ処理・保存をする側
- データベース（DB）― データを保存・検索する仕組み
- HTML / CSS / JavaScript ― 画面の構造／見た目／動きの基本3点

**🟡 重要**
- TypeScript ― JavaScriptに型（安全装置）を足したもの
- コンポーネント ― 画面を作る再利用できる部品
- 状態（state）― 画面が今持っているデータ
- レスポンシブ ― スマホ/PCで見た目を自動調整
- レンダリング ― データを画面の形に描き出す

**🟢 発展**
- SPA / SSR / SSG ― 画面の作り・描画タイミングの方式違い
- DOM ― ブラウザが扱う画面の構造データ
- キャッシュ ― 取ったものを取っておいて速くする
- 仮想DOM ― 差分だけ効率よく描き替える仕組み
- アクセシビリティ（a11y）― 誰でも使える配慮

## 7. データベース・データまわり

**🔴 必須**
- データベース（DB）― データを保存・検索する仕組み
- テーブル / レコード / カラム ― 表／行／列。データの入れ物
- 保存・取得・更新・削除（CRUD）― データ操作の基本4つ

**🟡 重要**
- SQL ― データベースを操作する言語
- クエリ ― データへの問い合わせ（検索・取得の命令）
- 主キー（ID）― 1件を一意に特定する目印
- リレーション ― テーブル同士のつながり
- バックアップ / リストア ― 控えを取る／戻す

**🟢 発展**
- NoSQL ― 表形式によらない柔軟なDB
- マイグレーション ― DB構造の変更を管理する
- スキーマ ― データの構造・設計図
- インデックス ― 検索を速くする索引
- トランザクション ― まとめて成功か失敗かにする処理

## 8. AI開発・LLM まわり（vibe coding の中核）

**🔴 必須**
- LLM（大規模言語モデル）― 文章を理解・生成するAIの本体
- プロンプト ― AIへの指示文
- トークン ― AIが文章を扱う最小単位。料金・上限の計算基準
- コンテキスト（文脈窓）― AIが一度に考慮できる情報量の範囲
- ハルシネーション ― AIがもっともらしい嘘を作ること

**🟡 重要**
- API経由でLLMを使う ― 自分のアプリにAIを組み込む（→3章API）
- システムプロンプト ― AIの役割・前提を決める土台の指示
- RAG ― 外部資料を参照させて回答精度を上げる
- エージェント ― 自分で道具を使い手順を踏んで動くAI
- 温度（temperature）― 回答のランダムさ・自由度の設定

**🟢 発展**
- エンベディング（ベクトル）― 文章を数値化し意味で検索可能にする
- ファインチューニング ― モデルを特定用途に追加学習
- MCP ― AIに外部ツール／データをつなぐ標準規格
- 推論（inference）― 学習済みモデルを実際に動かす
- マルチモーダル ― 画像・音声なども扱える
- プロンプトインジェクション ― 悪意ある入力でAIを乗っ取る攻撃

## 9. 開発環境・ツール

**🔴 必須**
- エディタ / IDE ― コードを書くアプリ（例: VS Code）
- ターミナル / コマンドライン（CLI）― 文字で命令してPCを操作する画面
- コマンド ― ターミナルに打つ命令文
- ログ ― プログラムが出す動作の記録（エラーの手がかり）

**🟡 重要**
- シェル（bash / zsh）― 命令を解釈する仕組み
- パス（PATH / ファイルパス）― ファイルの場所、コマンドの在りか
- 拡張機能 ― エディタに機能を足す追加部品
- デバッガ ― バグを調べる道具
- インストーラ / セットアップ ― 道具を入れる初期手順

**🟢 発展**
- コンテナ / Docker ― アプリを環境ごと箱に詰めて持ち運ぶ
- 仮想環境 ― プロジェクトごとに独立した実行環境を作る
- スクリプト ― 作業を自動化する小さなプログラム
- ホットリロード ― 保存したら自動で反映される
- リンター / フォーマッタ ― 書き方のミス検出・自動整形

## 10. クラウド・インフラの基礎

**🔴 必須**
- クラウド ― 自分で持たず、ネット越しに借りる計算資源
- サーバー ― 処理を受け持つコンピュータ（→2章と共通）

**🟡 重要**
- ホスティング / デプロイ先 ― アプリを置いて動かす場所
- サーバーレス ― サーバー管理を意識せず動かせる仕組み
- ストレージ ― データの保存場所
- 従量課金 ― 使った分だけ払う料金体系
- インスタンス ― 借りて起動した仮想コンピュータ1台

**🟢 発展**
- スケール（アップ / アウト）― 性能を上げる／台数を増やす
- 仮想マシン（VM）― 1台の中に作る仮想コンピュータ
- リージョン / ゾーン ― データセンターの地理的な場所
- IaaS / PaaS / SaaS ― クラウドの提供レベルの違い
- オートスケール ― 負荷に応じて自動で増減する

## 11. トラブル・デバッグでよく出る語

**🔴 必須**
- バグ / デバッグ ― 不具合／それを直す
- エラー ― 異常が起きてプログラムが知らせる状態
- エラーメッセージ ― 何が起きたかを伝える文（AIに貼って相談する基本）
- ログを見る ― 記録から原因を探す

**🟡 重要**
- 例外（exception）― 想定外で処理が止まる
- スタックトレース ― エラーがどこで起きたかの足跡
- 再現性 ― 同じ手順で同じ不具合が起きるか
- タイムアウト ― 待ち時間切れ
- クラッシュ / フリーズ ― 落ちる／固まる

**🟢 発展**
- ロールバック ― 前の状態に戻す
- 競合（race condition）― 同時処理がぶつかる不具合
- メモリリーク ― メモリを離さず溜め続ける不具合
- エッジケース ― 例外的な条件で起きる問題
- 切り分け（二分探索的デバッグ）― 原因範囲を半分ずつ絞る

**🟢 発展**

- Docker ― コンテナ技術の代表
- Figma ― デザインツール。開発と連携
- Stripe ― 決済を組み込むサービス

### 章をまたぐ重要語（横串でつながる＝「構造で理解」の見せ場）
- **トークン / APIキー**：4章(秘密)・3章(API)・8章(AI)で再登場 → 1つの概念が文脈で形を変える好例
- **環境変数**：2章(本番/開発切替)・4章(秘密管理) → 「コードの外に設定を出す」思想
